- [MEDIUM] web/app/(portal)/portal/appointments/[appointmentId]/MyAppointmentView.tsx:57 — the reschedule picker's starting date is `detail.startsOn.slice(0, 10)`, the UTC date, while everything else on the screen (`todayIso`, the slots query, the picker) is branch-local. It lands on the wrong day whenever the branch-local date differs from the UTC date: before 06:00 local for Asia/Dhaka (UTC+6), and for evening appointments in any zone west of UTC. For a Dhaka clinic open roughly 09:00-18:00 it is dormant, but a London or Americas branch hits it, and the clamp to `todayIso` hides the error. Fix: `localDateOf(detail.startsOn, zone)` (already exported from lib/format/time and used in CalendarView). Searched for the same pattern: the only other `.slice(0, 10)` / `toISOString()` uses are `addDaysIso` (UTC arithmetic on a date string, correct) and the .ics UTC stamp (correct). No other instance.

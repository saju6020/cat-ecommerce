Reviewed and found sound:
- Guest cart. `pc_cart` holds 32 random bytes, is HttpOnly, Secure, SameSite=Lax and IsEssential, and only its SHA-256 is stored. The server mints the token, and a client-supplied value never becomes a new cart's hash. Merge is an explicit POST that requires a customer session and expires the cookie. Customer carts are keyed by the session id.
- Ownership. Orders, returns and reorders go through `OrderAccess.ForCustomerAsync`, which returns 404 for anyone else's. Read queries filter by CustomerId. Cat names are filtered by owner. The delivery address is loaded by (customerId, addressId).
- Pricing. Placement and the counter sale recompute the quote on the server. The order takes the quote's own numbers, so the client never supplies a price. A fingerprint mismatch returns 409. Discount use is counted on the tracked code row, so concurrent last uses collide on xmin.
- Idempotency. The scope is caller kind + account id + route template, so a key cannot be reused across users. The hash covers method, path, query and canonical body. A different body returns 422 and a request still running returns 409. The authorization filter runs before this resource filter.
- Webhook. The provider must be configured with a secret (404 otherwise). The HMAC-SHA256 of the raw body is compared with FixedTimeEquals. The body is capped at 64 KB and is never logged. Duplicates are dropped by (provider, event_id) with ON CONFLICT, and receipts are never purged. A webhook cannot change order status. The endpoint is rate limited.
- Bank transfer. The amount must equal the total exactly. Above the threshold the payment is held, and the approver must differ from the recorder (`RequireHeldPaymentForApprover`). Billing records "recorded by" the first person and "approved by" the second. Customer and staff references go through the card-number refusal (C-5).
- Refunds. The `Refunds.Issue` roles apply. The amount must be no more than paid minus already refunded. The method is allowed only according to how the order was paid. A reference is required. A credit note is issued or linked in the same transaction. Double refunds are blocked by xmin on the tracked order and by Billing's unallocated balance.
- POS. `Pos.Sell` is scoped to the active branch. Tender maths are in minor units, a card tender cannot exceed the balance, and a card needs a slip reference. Amounts are validated to two decimal places. The receipt is limited to the active branch and to Counter/Delivered orders.
- Raw SQL is all parameterised (`ExecuteSqlInterpolated`), apart from one constant sequence name. Logs carry no PII, tokens or bodies. Notification variables carry no external URL. The tracking URL template must be https, with no userinfo, and the tracking number is escaped. The manifest CSV uses the ADR-051 formula guard. Request DTOs are mapped field by field, so there is no mass assignment.

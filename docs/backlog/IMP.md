Findings raised by more than one gate are one row, with every source listed. Gate finding ids: `ARCHITECTURE M3`,
`SECURITY L2` and so on are the finding's position within that gate's MEDIUM or LOW list (ARCHITECTURE, ACCEPTANCE
and R2 number or order them as written; SECURITY and CODE_REVIEW list them unnumbered, so the id is the order of
appearance); `T-n` are the TEST gate's own backlog ids. Two tags matter: **Owner decision** rows cannot be fixed until
the owner rules; **Integrator** rows are work only the integrator can do (migrations, registrations in other areas'
files, scheduling the SHP follow-up). Rows already closed by the follow-up rounds, the integrator's merge
resolutions or this paperwork are marked **Closed** and kept so the same finding is not re-raised.
